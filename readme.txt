ارسال خودکار و دستی درخواست ایندکس به Google Indexing API با داشبورد، ارسال گروهی، کنترل سهمیه و گزارش.

== Description ==

* ارسال خودکار URL_UPDATED هنگام انتشار/ویرایش و URL_DELETED هنگام حذف، لغو انتشار یا تغییر نامک
* بررسی وضعیت ایندکس (URL Inspection API) پیش و پس از ارسال
* بررسی پیش از ارسال (noindex، canonical، ۴۰۴، ریدایرکت) برای جلوگیری از هدر رفتن سهمیه
* IndexNow برای Bing و Yandex
* گزارش روزانه با ایمیل، بله یا تلگرام
* صف ارسال: بارگذاری فایل اکسل/CSV (مثلاً خروجی «صفحات ایندکس‌نشده» Search Console) و ارسال خودکار روزانه تا سقف تعیین‌شده
* داشبورد با مصرف سهمیه روزانه، نرخ موفقیت و فعالیت‌های اخیر
* ارسال گروهی تا صدها آدرس با نوار پیشرفت، توقف و نتیجه جداگانه برای هر آدرس
* بررسی وضعیت آدرس (urlNotifications.metadata)
* بارگذاری کلید سرویس اکانت با کشیدن و رها کردن و اعتبارسنجی فوری
* ستون وضعیت، دکمه «درخواست ایندکس» و Bulk Action در لیست نوشته‌ها
* متاباکس در صفحه ویرایش نوشته
* گزارش کامل با فیلتر، جستجو، راهنمای رفع خطا و خروجی CSV
* بدون وابستگی به کتابخانه‌های خارجی (JWT با OpenSSL)

نکته: گوگل این API را رسماً فقط برای صفحات دارای JobPosting یا BroadcastEvent داخل VideoObject پشتیبانی می‌کند.

== Installation ==

1. فایل zip را از «افزونه‌ها ← افزودن ← بارگذاری افزونه» نصب و فعال کنید.
2. در Google Cloud، Web Search Indexing API را فعال کنید و یک سرویس اکانت با کلید JSON بسازید.
3. ایمیل سرویس اکانت را در Search Console با نقش Owner اضافه کنید.
4. از منوی «Indexing API ← تنظیمات» فایل JSON را بارگذاری کنید و «تست اتصال» را بزنید.

برای امنیت بیشتر می‌توانید به جای ذخیره کلید در دیتابیس، در wp-config.php بنویسید:
define( 'SGIA_KEY_FILE', '/path/outside/public_html/key.json' );

== Changelog ==

= 2.3.1 =
* اگر دو نسخه از افزونه هم‌زمان فعال باشند (مثلاً پوشه قدیمی تغییرنام‌داده اما فعال)، دیگر خطای مهلک رخ نمی‌دهد؛ پیام می‌دهد یکی را غیرفعال کنید
* حذف یک نسخه وقتی نسخه دیگری هنوز نصب است، تنظیمات، کلید و صف مشترک را پاک نمی‌کند

= 2.3.0 =
* سرعت صف: بررسی صفحه، بررسی ایندکس و ارسال به گوگل برای هر دسته به‌صورت هم‌زمان انجام می‌شود (روی سایت زنده هر آدرس حدود ۱۱ ثانیه طول می‌کشید و هر اجرا فقط ۲ آدرس می‌فرستاد؛ اکنون تا ۱۵ آدرس در هر اجرا)
* بررسی دوباره ایندکس پس از ارسال در هر اجرا سهم ثابت دارد، حتی وقتی صف متوقف است یا سقف روزانه پر شده
* رفع: پس از ارسال یک نوشته فارسی از صف یا تب «ارسال»، ویرایش بعدی آن ممکن بود به اشتباه «حذف صفحه» (URL_DELETED) به گوگل اعلام کند
* ذخیره‌های پشت‌سرهم یک نوشته تا ۳۰ دقیقه بعد از ارسال موفق، دوباره سهمیه مصرف نمی‌کنند
* فقط درخواست‌های پذیرفته‌شده توسط گوگل در سهمیه روزانه شمرده می‌شوند
* قفل اجرای صف اتمی شد؛ دو اجرای هم‌زمان یک آدرس را دو بار نمی‌فرستند
* خطای تشخیص property در Search Console یک ساعت به خاطر سپرده می‌شود (نه یک درخواست اضافه برای هر آدرس)
* درج صف با INSERT IGNORE؛ تکراری هم‌زمان کل دسته را از دست نمی‌دهد
* توکن ربات دیگر در HTML صفحه تنظیمات نوشته نمی‌شود
* داشبورد: «نرخ موفقیت امروز» از شمارنده‌های روزانه؛ شمارش فیلتر «ایندکس‌شده» با فهرستش یکی شد؛ نتیجه و زمان آخرین اجرای صف نمایش داده می‌شود
* هشدار Rank Math فقط وقتی هر دو IndexNow روشن‌اند؛ زمان واقعی ریست سهمیه در متن گزارش روزانه
* IndexNow: در خطای موقت، آدرس‌ها دوباره در صف ارسال قرار می‌گیرند
* حذف افزونه فایل کلید IndexNow را هم پاک می‌کند

= 2.2.0 =
* بررسی وضعیت واقعی ایندکس با URL Inspection API: پیش از ارسال (صفحه‌های ایندکس‌شده ارسال نمی‌شوند) و چند روز بعد از ارسال (نرخ ایندکس پس از ارسال)

* ووکامرس: اولویت محصولات تازه و پرفروش در صف، رد کردن محصولات ناموجود
* گزارش روزانه با ایمیل، بله یا تلگرام، و هشدار فوری هنگام توقف ارسال
* هشدار سلامت WP-Cron و دستور آماده Cron Job هاست
* API یکپارچه‌سازی برای افزونه‌های دیگر (از شاخه gscii-integration): SGIA_Queue::import( $urls, $source )، SGIA_Queue::lookup( $urls )، SGIA_Queue::capacity_today()، اکشن sgia_published
* داشبورد: کارت‌های ایندکس پس از ارسال، صف، سهمیه صرفه‌جویی‌شده و IndexNow
